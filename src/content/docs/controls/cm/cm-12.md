## Control statement

- **a.** Identify and document the location of [Assignment: organization-defined information] and the specific system components on which the information is processed and stored;
- **b.** Identify and document the users who have access to the system and system components where the information is processed and stored; and
- **c.** Document changes to the location (i.e., system or system components) where the information is processed and stored.

<details>
<summary>NIST discussion</summary>

Information location addresses the need to understand where information is being processed and stored. Information location includes identifying where specific information types and information reside in system components and how information is being processed so that information flow can be understood and adequate protection and policy management provided for such information and system components. The security category of the information is also a factor in determining the controls necessary to protect the information and the system component where the information resides (see FIPS 199 ). The location of the information and system components is also a factor in the architecture and design of the system (see SA-4, SA-8, SA-17).

</details>

### CM-12(1) Automated Tools to Support Information Location

*Baselines: Moderate, High*

Use automated tools to identify [Assignment: organization-defined information by information type] on [Assignment: organization-defined system components] to ensure controls are in place to protect organizational information and individual privacy.

<details>
<summary>Discussion and assessment objectives for CM-12(1)</summary>

The use of automated tools helps to increase the effectiveness and efficiency of the information location capability implemented within the system. Automation also helps organizations manage the data produced during information location activities and share such information across the organization. The output of automated information location tools can be used to guide and inform system architecture and design decisions.

Determine if automated tools are used to identify [Assignment: organization-defined information by information type] on [Assignment: organization-defined system components] to ensure that controls are in place to protect organizational information and individual privacy.

**Examine:** Configuration management policy; procedures addressing identification and documentation of information location; configuration management plan; system design documentation; PII inventory documentation; data mapping documentation; change control records; system component inventory; system security plan; privacy plan; other relevant documents or records.

**Interview:** Organizational personnel with responsibilities for managing information location; organizational personnel with information security responsibilities; system/network administrators; system developers.

**Test:** Organizational processes governing information location; automated mechanisms enforcing policies and methods for governing information location; automated tools used to identify information on system components.

</details>

## How to apply it

CM-12 asks you to know where specific information lives: which components process and store it, who has access to those components, and when that changes. NIST's CM-12 discussion ties this to understanding information flow, so the information and the components that hold it get the right protection, and notes that the information's security category (FIPS 199) helps decide which controls those components need. Where information is located also shapes the system's architecture and design ([SA-4](/controls/sa/sa-4/), [SA-8](/controls/sa/sa-8/), [SA-17](/controls/sa/sa-17/)).

**Common implementations.** A data map for the system that lists each information type from the [system security plan](/templates/plans/system-security-plan/), section 6, with the databases, storage, file shares, cloud services and regions, backups and endpoints where it is processed and stored. The components the map names are the ones in the component inventory ([CM-8](/controls/cm/cm-8/)). Access to those components comes from the account lists kept under [AC-2](/controls/ac/ac-2/). A change that moves information to a new location, such as a new cloud region, storage service or backup target, goes through change control ([CM-3](/controls/cm/cm-3/)) and updates the map. For personal information, the [privacy impact assessment](/templates/reports/privacy-impact-assessment/) describes the same flows, so keep the two consistent.

**Organization-defined parameters.** Typical values, which your organization may set differently:

| Parameter | Typical value |
| --- | --- |
| Information whose location is documented (a) | The information types listed in the system security plan |
| Information types the automated tools look for (CM-12(1)) | Personal information and other sensitive information types listed in the system security plan |
| Components the automated tools scan (CM-12(1)) | File shares, databases, cloud storage and endpoints |

In the [Configuration Management policy](/templates/policies/cm/), the system owner identifies and documents the locations, the users with access and changes to the locations.

**Evidence assessors ask for.**

- The data map or equivalent, listing each information type and where it is processed and stored
- The users and roles with access to those components
- Change records that updated the map when information moved
- Scan results from the automated discovery tools, and the follow-up on information found where it should not be (CM-12(1))

**Inheritance.** Data discovery tools are often common. Each system owns documenting where its information lives, so CM-12 is usually a hybrid control.

**Common findings.**

- A data map that leaves out backups, logs, analytics copies or test environments holding production data.
- Information found by discovery scans in locations the map does not list.
- Cloud regions or services added without updating the map.
- No list of who can access the components that hold sensitive information.

**Enhancements in the Moderate baseline.** [CM-12(1)](#cm-12.1) automated tools to support information location, which is also in High. Data discovery or data loss prevention tools scan file shares, databases, cloud storage and endpoints for personal and other sensitive information, so you can confirm controls are in place where the information actually is. NIST's discussion notes the results can also guide architecture and design decisions.
